# Quickstart Backlog — todo

Generated by `/quickstart` on 2026-07-22. Product owner: Pat. Sprint planner: Grace.

## Sprint 1

- [x] **TODO-1: Add a todo item** (S)
  `todo add "Buy milk"` appends a new item with auto-incrementing ID, stored in `~/.todo/todos.json`. Default status is "pending."
  _Acceptance criteria:_ `todo add "Buy milk"` prints confirmation with assigned ID / item is persisted to JSON / `todo add ""` raises an error.

- [x] **TODO-2: List todo items** (S)
  `todo list` prints all items with ID, text, and status (pending/done).
  _Acceptance criteria:_ After adding 2 items, `todo list` shows both with IDs and "pending" status / empty list prints "No todos yet."

- [x] **TODO-3: Complete a todo item** (S)
  `todo done <id>` marks an item as completed.
  _Acceptance criteria:_ After `todo done 1`, item 1 shows "done" status in `todo list` / `todo done 999` raises an error for non-existent ID.

## Later

- [ ] **TODO-4: Delete a todo item** (S)
  `todo delete <id>` removes an item from the store.

- [ ] **TODO-5: Filter by status** (S)
  `todo list --status pending` or `todo list --status done` filters the output.

## Notes

- All Sprint 1 items are independent — no ordering dependency between TODO-2 and TODO-3.
- Items are sized S because each involves a single subcommand with straightforward JSON I/O.
- Architecture Gate not required — standard file I/O, no new patterns.
